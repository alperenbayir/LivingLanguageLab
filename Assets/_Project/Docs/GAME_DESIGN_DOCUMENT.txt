1. CORE GAME LOOP
================================================================================

DESCRIPTION:
Kitchen Scene → 60% Completion → Alert User → Light Game Available → 
One Round Per Article → Player Must Finish Once Started → 
Player Can Play Multiple Times → Exit Scene → Quiz Scene

FEASIBILITY: ✅ HIGHLY FEASIBLE

IMPLEMENTATION NOTES:
- Current system tracks discovered items via SentenceHistoryManager
- Progress calculation: discoveredCount / totalCount
- Need to add:
  * Completion percentage check (60% threshold)
  * Alert system (audio/SFX notification)
  * Light game unlock mechanism
  * Scene transition manager
  * Article-based game progression system

TECHNICAL REQUIREMENTS:
- GameStateManager to track scene completion
- Audio/SFX system for alerts (already partially implemented)
- Light game state management
- Scene loading system for quiz transition

PRIORITY: HIGH (Core gameplay loop)

2. WIT.AI INTEGRATION & PRONUNCIATION FEEDBACK
================================================================================

DESCRIPTION:
- Speak button on press: 4-5 seconds speaking time
- Disable other buttons while speaking
- Wit.ai converts speech to text
- Display old algorithm percentage OR red-yellow-green feedback
- Overwrite sentence text in SmartTablet
- User can retry pronunciation

FEASIBILITY: ✅ FEASIBLE (Partially Implemented)

CURRENT STATE:
- Wit.ai integration exists (AppVoiceExperience component found)
- SmartLearningPanel has OnVoiceResult callback
- Button layout exists but needs organization
- TabletDisplay has sentence text display

IMPLEMENTATION REQUIREMENTS:
1. Speak Button Functionality:
   - Record for 4-5 seconds on button press
   - Disable other UI buttons during recording
   - Visual feedback (button state, timer)

2. Wit.ai Integration:
   - Already configured (witConfiguration.asset exists)
   - Need to connect to pronunciation scoring
   - Text transcription already working

3. Feedback System:
   - Option A: Percentage score (0-100%)
   - Option B: Color-coded feedback (Red < 60%, Yellow 60-80%, Green > 80%)
   - Recommendation: Use color-coded for better UX

4. Sentence Overwrite:
   - Modify TabletDisplay.sentenceText when pronunciation is attempted
   - Show transcribed text from Wit.ai
   - Allow retry mechanism

TECHNICAL CHALLENGES:
- Pronunciation accuracy scoring (may need custom algorithm or Wit.ai confidence score)
- Button state management during recording
- UI layout organization (mentioned as "not organized" in hierarchy)

PRIORITY: HIGH (Core learning feature)

================================================================================
3. LIGHT GAME (ARTICLE GAME)
================================================================================

DESCRIPTION:
- Emphasize article codes (der/die/das) - articles ready in JSON (3/5 complete)
- Scoring and progression to next article
- Collected count, remaining time
- Time based on total interactable count
- UI decision: separate interface or integrate with existing tablet

FEASIBILITY: ✅ FEASIBLE

CURRENT STATE:
- LightGameLayout GameObject exists in scene (inactive)
- Vocabulary JSON has "article_only" field for all items
- Article distribution in current JSON:
  * Der: 8 items (fish, pot-stew, mustard, knife-block, turkey, plate, oven, toaster)
  * Die: 14 items (cup-coffee, pan, bratwurst, fries, can, fork, tomato, onion, orange, lemon, paprika, microwave, coffee-machine)
  * Das: 7 items (cutting-board, egg, cooking-knife, meat, ketchup, knife, bottle-oil)
  * Total: 29 items (need 50 as mentioned in misc section)

IMPLEMENTATION REQUIREMENTS:

1. Article Emphasis Mechanics:
   - Visual highlighting of article codes (der/die/das)
   - Could use color coding: Der (blue), Die (red), Das (green)
   - Audio emphasis on article pronunciation
   - Visual indicators on objects in VR space

2. Scoring System:
   - Points for correct article identification
   - Progression tracking per article type
   - Completion status for each article category

3. Time Management:
   - Dynamic time calculation: baseTime + (interactableCount * timePerItem)
   - Example: 60 seconds base + (29 items * 2 seconds) = 118 seconds
   - Display countdown timer
   - Show collected/total count

4. UI Design Decision:
   RECOMMENDATION: Separate Light Game UI
   - Better for focused gameplay
   - Can show article-specific information
   - Less cluttered than integrating with tablet
   - Can reuse tablet layout structure but with different content

5. Game Flow:
   - One round per article type (Der, Die, Das)
   - Player must complete round once started (no mid-game exit)
   - Can replay completed rounds
   - Track best scores per article type

TECHNICAL REQUIREMENTS:
- LightGameManager script
- Article-based filtering from VocabularyManager
- Timer system
- Score tracking system
- UI for light game (separate or integrated)
- VR interaction system for selecting objects

PRIORITY: HIGH (Core gameplay feature)

4. QUIZ SYSTEM
================================================================================

DESCRIPTION:
- Questions about learned vocabulary
- Number of questions (TBD)
- AI-generated story at end showing interaction statistics
- Highlight less-interacted objects
- Quiz menu design
- Radial UI for answer choices
- Question content scope
- Auto-generated scene scalability (1/5 feasibility)

FEASIBILITY: ⚠️ PARTIALLY FEASIBLE

IMPLEMENTATION REQUIREMENTS:

1. Question Content:
   RECOMMENDATION: Focus on vocabulary learned in kitchen scene
   - Article identification (der/die/das)
   - Word meaning (German to English)
   - Sentence completion
   - Pronunciation recognition
   - Suggested: 10-15 questions per quiz

2. AI-Generated Story:
   FEASIBILITY: ✅ FEASIBLE
   - Use existing SentenceGenerator (LLM integration)
   - Input: interaction statistics (objectID, interaction count)
   - Generate personalized story mentioning objects
   - Highlight objects with low interaction count
   - Format: "You spent a lot of time with [object], but [less-interacted object] was lonely..."

3. Quiz Menu Design:
   - Start quiz button
   - Progress indicator
   - Results screen
   - Story display area
   - Statistics visualization

4. Radial UI for Answers:
   FEASIBILITY: ✅ FEASIBLE
   - Unity UI system supports radial layouts
   - 4 answer choices in circular arrangement
   - VR-friendly selection (gaze or hand interaction)
   - Visual feedback on selection

5. Auto-Generated Scene Scalability:
   FEASIBILITY: ⚠️ MODERATE (2/5)
   CHALLENGES:
   - Scene generation requires 3D model placement
   - Object interaction setup
   - Lighting and environment design
   - Performance optimization
   - Quality control
   
   RECOMMENDATION: 
   - Start with manually designed scenes
   - Consider procedural object placement (easier)
   - Full scene generation is complex and may not be necessary
   - Focus on content variety instead of scene generation

TECHNICAL REQUIREMENTS:
- QuizManager script
- Question database/structure
- Answer selection system
- Scoring system
- Statistics tracking (interaction counts)
- Story generation integration
- Radial UI components
- Scene transition system

PRIORITY: MEDIUM-HIGH (Important for learning validation)

8. TECHNICAL ARCHITECTURE RECOMMENDATIONS
================================================================================

MANAGER STRUCTURE:
- GameStateManager (singleton) - Tracks scene completion, game state
- LightGameManager - Handles article game logic
- QuizManager - Manages quiz flow and scoring
- PronunciationScorer - Handles Wit.ai feedback and scoring
- StatisticsTracker - Tracks interactions for story generation

DATA STRUCTURES:
- ArticleGameData - Stores article game progress
- QuizQuestion - Question structure
- InteractionStats - Tracks object interactions
- PlayerProgress - Overall progress tracking

UI SYSTEM:
- TabletDisplay (existing) - Main tablet UI
- LightGameUI - Separate UI for article game
- QuizUI - Quiz interface with radial answers
- ResultsUI - Quiz results and story display
